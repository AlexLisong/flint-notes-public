# Integration contract

This document describes the API shared by the browser and folder companion. See [architecture](architecture.md) for component responsibilities.

All API JSON, same-origin session cookie or bearer device token. Authenticated browser writes include X-CSRF-Token from /api/auth/me. Errors {error,code?}. UUID ids. Dates ISO. Types in shared/types.ts. All private ciphertext uses shared/crypto.ts implementation in this repository.

- POST /api/auth/register {email,name,password,code?,invite?} -> Session. Registration code or live invitation required.
- POST /api/auth/login {email,password} -> Session. GET /api/auth/me -> Session. POST /api/auth/logout.
- GET /api/vaults -> {vaults:Vault[]}. POST /api/vaults {id,name,salt,keyBox} -> {vault:Vault}. Encryption key is client-only.
- GET /api/vaults/:id/files?after=0 -> ChangePage. Pagination returns up to 500 current heads, including tombstones; pass cursor as after until hasMore=false. Replace local records only with the same or newer revision.
- GET /api/vaults/:id/manifests?after=0 -> {files:FileManifest[],cursor,hasMore}. Same cursor pagination, with encrypted manifestBox and revision metadata but no note content box. Decrypt manifests locally before fetching allowed files; legacy records without manifestBox require a full-record fallback. GET /api/vaults/:id/files/:fileId?revision=N -> {file:FileRecord}; omit revision for the current head. A requested revision that was pruned returns404.
- GET /api/vaults/:id/files/:fileId/history?before=N -> {files:FileRecord[],hasMore,nextBefore}. Newest first, up to100 retained revisions per page; omit before for the newest page and pass nextBefore for older pages. Historical records need not contain manifestBox.
- PUT /api/vaults/:id/files/:fileId FileWrite -> {file:FileRecord}. FileWrite includes optional manifestBox, encrypted separately with the vault/file/revision/epoch/deletion binding. Its base64 data is limited to8192 characters; the content box data is limited to2,000,000 characters. HTTP409 includes {error,file?:FileRecord};412 means the encryption epoch changed. mutationId replay returns the original result for30 days; reusing it with different content fails. After retry history expires, baseRevision still prevents overwriting a newer revision. baseRevision0 creates; the expected current revision updates. Server storage usage includes current encrypted content/manifests, retained revisions, replay responses, immutable chunks and published plaintext/assets. Capacity is checked before mutations;413 leaves the previous head intact.
- PUT /api/vaults/:id/chunks/:uuid raw encrypted octets max 2 MiB -> {id}. GET same -> bytes. Crypto chunk binding includes vaultId and chunk UUID. Files store encrypted attachment pointers. Chunks immutable, authenticated per vault.
- GET /api/vaults/:id/members -> {members:[{id,email,name,role}]}. POST /api/vaults/:id/invites {role:'viewer'|'editor'} -> {token,url}. POST /api/invites/:token/accept -> {vault:Vault}; viewer cannot write. Share vault unlock phrase separately from invitation. DELETE /api/vaults/:id/members/:userId revokes future API access; owner cannot remove self. POST /api/vaults/:id/rotate performs owner-authorized key rotation; see the request schema in `shared/types.ts` and server validation.
- POST /api/devices {name,vaultId} -> {token,id}. GET /api/devices -> {devices:[{id,name,vaultId,createdAt,lastUsedAt}]}. DELETE /api/devices/:id. Tokens restricted to named vault, cannot manage members/publish. Pairing credentials downloadable in UI (requires an unlocked client keyring).
- GET /api/vaults/:id/sites -> {sites:Site[]}. POST /api/vaults/:id/sites {slug,title} -> {site:Site}. PUT /api/sites/:id PublishInput replaces the public snapshot atomically (owner only, expectedRevision required); an over-quota or stale update preserves the previous snapshot. DELETE /api/sites/:id/publication unpublishes all. GET /api/sites/:id/publication -> {notes:PublishedNote[],revision} authenticated owner. GET /api/published/:slug -> {site,notes,assets} (401 SITE_PASSWORD if protected); POST /api/published/:slug/unlock {password}; GET /api/published/:slug/assets/:id uses the same password gate. In-flight unlocks revalidate publication/password state before creating a session. Public rendering routes are /p/:slug and /p/:slug/:noteSlug; percent-encode each URL segment. Site slug: lowercase ASCII letters, numbers and hyphens,3–64 chars. Note slug: Unicode letters/numbers and hyphens,1–200 chars. No private files are included implicitly; only selected decrypted notes/assets are uploaded.
- GET /api/health -> {ok:true}. GET /api/vaults/:id/usage -> {bytes,limitBytes,fileCount,retentionDays}. POST /api/vaults/:id/retention {days} owner (30..3650).

Offline client: encrypted IndexedDB rows and durable encrypted outbox. Keys only in memory after unlock. Queue writes with original baseRevision; conflicts preserve local content as a new conflict copy and fetch the remote canonical version. Automatic poll/change modes run while the app is open. Service worker caches the app shell only, never private/public API data. Per-device selective sync decrypts the small encrypted manifest before fetching included content; attachment bytes download on demand. Do not put raw keys/passphrases in localStorage. Retention cleanup runs at startup/hourly and when changing retention; current heads and tombstones remain available.
